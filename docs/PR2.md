## 〇、方案变更说明(需要评审关注)

原定「微信同声传译插件」(免费、官方、实时转写)**不支持个人主体小程序添加**(仅企业/个体工商户可用,实测后台搜索不可见)。改用:

> **原生录音(wx.getRecorderManager,wav/16k/单声道)→ base64 → 新增 transcribe 云函数(腾讯云一句话识别)→ 文字 → 既有提取链路**

- 这恰好回到 issue #1 最初的模型最窄入口设计:`transcribe(audio) -> text` 与 `extract_items(text, ...)` 分离;
- 新增第三个云函数 `transcribe`(无状态、不落库、输入输出即焚),与 F1「两类云函数」的裁定有出入,**提请架构评审确认**;密钥管理沿用既有约定(TENCENT_SECRET_ID/KEY 仅云函数环境变量);
- 代价:无实时转写上屏(录完识别,识别中状态呈现);ASR 有少量费用(免费额度内)。

## 一、实现了什么

- **首页「记一件」双模式**:文字(原有)/ 语音(新增)切换;
  - **按住说话**:按下开始录音(显示录音秒数),松开停止并识别("识别中…"状态)
  - **上滑取消**:录音中向上滑动超过阈值进入"松手取消"状态,松手丢弃本次结果;滑回可恢复
  - **识别完成自动接提取**:转写文本自动填入并触发 extractDraft——录音→转写→AI 提取→确认一条龙
  - **文字回退**:任何失败(录音失败/太短/读文件失败/识别失败/密钥未配)都有明确中文提示与文字回退;AI 不可用手动录入(PR1 既有)
- **授权与隐私**:`scope.record` 授权流(预检 + 拒绝引导 openSetting);后台「用户隐私保护指引」需声明麦克风(已配置);音频 base64 仅经 callFunction 进 transcribe,**日志只记音频大小/格式/耗时/错误码,绝不打印音频数据与识别结果**
- **耗时埋点**(issue 要求的耗时分解):每次录音记录 按住时长/转写耗时(含云函数+ASR)/字数,本地保留 50 条,p50 聚合(离线可测)

### 二轮评审修复:录音会话全生命周期化(2026-10-10)

会话标识从页面层**下沉到控制器**,贯穿启动、取消、转写全部异步回调:

- `VoiceController.begin()` 签发会话;**新会话开始即永久作废旧会话**(含在途 ASR),旧结果不可能"复活"
- `recorder.onStart` 迟到回调:会话已作废 → 立即停止录音、不回调页面、不上传(评审场景:松手早于启动回调)
- `stop(session)` 在录音尚未实际启动时调用 → 按作废处理(停止且不上传)
- 转写返回时二次校验会话(被取消或已被替代 → 丢弃)
- 页面级 `SessionGuard` 仅负责授权异步窗口;切换模式/回退文字/onHide/onUnload 统一经 `invalidateVoiceSession()` 作废会话
- 回归测试覆盖评审点名的两组场景:迟到启动(停止且不上传)、旧结果复活(A 被替代后返回必丢弃且 B 正常完成)

### 三轮评审修复:转写阶段可取消 + 取消不上传(2026-10-10)

- **松手 ≠ 处理结束**:页面在松手后**保留会话引用**直到 onStop/onError(处理完成)才释放;识别中切换文字模式/退后台经 invalidateVoiceSession → cancel(session) 真正取消在途 ASR,旧结果不可能再触发提取(此前松手即清空引用,识别中的会话无人能取消)
- **取消不上传**:控制器在读文件完成后、调用转写**之前**增加会话校验——读文件期间被取消/替代的会话不再上传音频
- 回归测试:③松手后转写阶段取消 → ASR 返回丢弃;④读文件期间取消 → `uploaded.length === 0` 且无任何结果回调
