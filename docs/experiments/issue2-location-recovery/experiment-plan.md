# #2 位置找回恢复 V0:最小交互实验计划(手工模拟,零生产改动)

> 定位:issue #2 V0「冻结基线与手工流程」。**docs-only,不编码、不新增生产 schema、不新增位置状态模型、不动 `miniprogram/` 与 `cloudfunctions/`**。「找到了 / 没在这里 / 待核实」全部用纸面卡 + #45 原型 toast 模拟(Wizard-of-Oz,纪律同 `docs/experiments/issue36-reminder-validation/D1-woz-scripts.md` §0);唯一的真实写入是**既有**「编辑物品信息」保存路径。生产启用(双钮写库)依 #2 另行授权,本文不构成授权。
> 裁定依据:工作流裁定(2026-10-15)「高频移动物为主、每件故意移位→找→纠正、先手工模拟不增字段」;#45 十一轮冻结(见 §5.3)。
> 配套文件:[sample-and-tasks.md](./sample-and-tasks.md)(样本冻结 + 任务脚本 + 记录模板)。

## 1. 研究问题与假设对齐

| #2 原假设 | 本轮是否直接检验 | 说明 |
| --- | --- | --- |
| H1 长期稳定物「上次确认位置」已够用;高频移动物更易失效 | **只做侧写,不做分组对比** | 裁定收窄:样本以高频移动物为主(≥14/20),稳定物仅作锚点(≤6/20);登记「类别 + 首次确认时间」,为 V2 真实观察留分组口径。本轮人为移位制造失真,测不出自然失效率,不冒充 H1 结论 |
| H2 「没在这里 → 待核实 → 一键修正」恢复路径能减轻错误事实传播,而非增加混乱 | **是,主问题** | 每件物品走完整闭环(L1–L6),量化:恢复成功率、步数、耗时、旧线索是否帮上忙、用户是否想跳过待核实直接猜新位置 |
| H3 在实际移动/找到时刻顺手更新,比独立打开应用维护库存更可能被采用 | **是,副问题** | L5 纠正动作嵌在「刚找到」的当下完成;对照问句见 sample-and-tasks.md §3 收尾访谈 |

**证伪优先**:若恢复路径平均耗时/步数超过用户容忍、或「没在这里」反馈没有帮助回忆(纯仪式感),即向 STOP 倾向,先收窄再考虑加字段(#2 原则:先证伪再增加字段)。

## 2. 交互闭环定义(L0–L6)

~~~text
L0 基线录入(既有生产入口,真实写)
   ↓ 间隔 ≥24h(避免刚录完的记忆红利)
L1 搜索「找东西」(既有生产链路,零新增)
   ↓ 命中 → 进详情
L2 详情页只读大卡「上次记在」+ 原话 +「可能已移动」(既有生产 UI)
   ↓
L3 首访判定:按记录位置实地找
   ├─ 就在记录位置 → 「找到了」(纸面:confirmed 不变,模拟刷新确认时间)→ 结束本件
   └─ 不在 → 「没在这里」(纸面:confirmed → uncertain)
        ↓
     L4 待核实态(纸面):旧 location_text 保留为线索,卡片文案变「位置待核实,上次说在:…」
        ↓  不猜新位置、不删旧线索;人肉找
     L5 找到后更新位置(既有编辑折叠表单,expected_version + update_id,真实写)
        ↓  冲突自然出现时走 #6/PR #12 四字段面板,如实记录
     L6 再搜一次 → 「找到了」确认新位置(纸面:uncertain → confirmed,模拟刷新确认时间)
~~~

### 2.1 逐步界面与动作规范

| 步 | 用什么 | 界面/动作 | 写入 | 打点 |
| --- | --- | --- | --- | --- |
| L0 录入 | 生产首页「按住说话 / 文字」+ 确认卡 | 20 件按 sample-and-tasks.md §1 冻结清单录入;位置须真实、指代清楚(空间路径或明确原话) | **真实写**(既有 create 合同,幂等 `operation_id`) | `t_entry_*`;首确认时间=本步,写入登记表 |
| L1 搜索 | 生产首页找东西(`miniprogram/pages/index/index.wxml:68`) | 输入物品名(用平时会怎么找就怎么输,不规定话术) | 无 | `t_search_ms`、`match_type`、是否首选命中 |
| L2 展示 | 生产详情只读大卡(`miniprogram/pages/item/item.wxml:13,33`) | 大声读出看到的「上次记在 + 原话」再去实地找 | 无 | 用户第一反应原话(照录);是否误以为「现在就在这」 |
| L3 找到了(支线) | **纸面双钮卡**(话术与 #45 原型 D1 一致:「找到了」) | 实地确在记录位置才可按;按=确认**就在该位置** | **纸面**:confirmed 不变,`confirmed_at ← now`(模拟) | `t_locate_ms`(进详情→按下);是否想按但没找先按(误点计) |
| L4 没在这里 | 纸面双钮卡「没在这里」 | 按=记录置 `uncertain`;纸面卡立即换「待核实」面:旧位置原话**原样保留** +「想想上次用它是什么时候?」提示句(**不出现任何新位置猜测**) | **纸面**:state←uncertain,旧线索留存 | `t_feedback_ms`;用户是否自发利用旧线索回忆(照录原话) |
| L5 更新位置 | 生产详情「编辑物品信息」折叠(`miniprogram/pages/item/item.wxml:45-52`) | 人肉找到后,就地打开表单改 `location_text` → 保存(既有 `itemsApi.update`:`expected_version` + `update_id`;`docs/API_CONTRACT.md:48`) | **真实写**(既有生产能力,非新字段) | `t_edit_ms`;若弹四字段冲突面板(自然并发才有):`conflict_hit=true` + 处理方式照录 |
| L6 再确认 | 纸面双钮卡「找到了」 | 回到搜索再搜一次 → 大卡已是新位置 → 实地确认 → 按「找到了」 | **纸面**:uncertain→confirmed,`confirmed_at ← now`(模拟) | `t_recheck_ms`;再搜是否仍首选命中 |

### 2.2 手工模拟纪律(Wizard 纪律,对齐 #36 D1 §0)

1. **纸面状态只有两类** `confirmed | uncertain`(#2 合同),绝不发明「过期评分 / 可疑度」;状态翻转只在用户显式动作后发生。
2. **「找到了」≠ 顺手确认**:必须在记录位置(或 L5 后的新位置)**亲眼见到物品**才可按;研究员不得代按、不得催促。
3. **「没在这里」零猜测**:待核实面只保留旧线索与提示句;任何「会不会在…」的推测只发生在用户脑内,照录原话,不进纸面卡。
4. **人工延迟如实记录**:纸面翻转、读卡、访谈均为人工操作,耗时打点照录,绝不美化为产品能力。
5. **口径诚实红线**:生产大卡的「记录更新于 MM-DD」是 `updated_at`,名称/备注/位置任意修改都会刷新,**不代表位置确认时间**(`miniprogram/pages/item/item.ts:49,109`)。试验一切「上次确认时间」以登记表纸面时间为准;报告不得把界面日期说成确认日期。
6. **每件物品的纸面卡独立编号**,试验后按匿名编号誊录(去标识化规则见 sample-and-tasks.md §5)。

## 3. 样本与任务(冻结,详见配套文件)

- **20 件真实物品,高频移动物为主(≥14),稳定锚点(≤6)**;选择标准、排除标准、登记表见 [sample-and-tasks.md](./sample-and-tasks.md) §1。清单定稿后冻结,不中途换样。
- **统一任务脚本(每件,无分组差异)**:故意移位 → 找 → 纠正(8 步打点,含 L3/L6 两次「找到了」机会);逐步脚本见同文件 §3。
- **会话**:2–4 个 session(每 session 5–8 件),顺序抽签;每件只跑一次,不重跑。
- **冲突演练(可选支线,≤1 件)**:由参与人用第二台设备在 L5 前抢先改一次位置,制造自然 `VERSION_CONFLICT`,观察冲突面板在「刚找到想马上改」情境下的负担;仅记录,不作为主指标。

## 5. 边界与授权(本轮不可越)

### 5.1 生产启用仍待授权

- 「找到了」刷新 `location_confirmed_at`、「没在这里」置 `uncertain` 的**写库实现本轮一概不做**;生产 schema 无此字段亦无此状态(`docs/API_CONTRACT.md:40` 的 items 字段清单为准),本轮零新增。
- 纸面模拟的 `confirmed_at / uncertain` 只是研究仪器,试验结束不落库、不迁移到任何生产数据。
- L5 的真实写是**既有**手动更新能力(任何用户今天都能做),不是为实验新开的口子;若未来 #2 GO,生产实现仍须单独 PR + 合同测试(#2 V1 清单:未经用户确认不更新 / 重复提交不重复变更 / 跨家庭无权 / 同名先消歧 / 状态与事实不混淆)。

### 5.2 数据与隐私红线

- 试验写入默认在**「我的家」个人家庭**进行,不污染共享家庭;如需在共享家庭测多人场景,另行明确授权。
- 不跑自动化 E2E、不批量造数据、不碰他人家庭;移位只动参与人自己家的物品,试验后物品留在新位置(记录与现实现实一致),参与人自行整理时顺手再更新(可如实追加为样本外记录,不入 20 件分母)。
- 证据去标识化:位置文本、真实住址、家人姓名不入公开报告(#2 Exit 要求);登记表本地保存。

### 5.3 与 #45 D1 双钮(冻结口径)的衔接

- #45 十一轮冻结裁定(2026-10-14,`docs/design/issue45-v02/issue45-handoff.md:149,198`):物品详情只读大卡已落地,**「找到了 / 没在这里」双钮本期不上**,依赖 #2 的 `location_confirmed_at` 写库授权,「双钮与位置过期提醒随 #2 立项评审」。
- 本实验就是该评审的**证据供给方**:纸面双钮话术、按钮含义、待核实卡文案全部照抄 #45 原型 D1 规格(`issue45-handoff.md:57`:找到了=观察原型 toast 模拟、不写库;没在这里=展开「待核实 / 修改位置」建议、不猜新位置),确保实验结论可直接外推到未来落地形态,不存在「实验一套话术、上线另一套」。
- 实验结束输出一页结论后,#2 走 GO/ADJUST/STOP(§6);GO 时双钮的生产落地按 #45 D1 规格 + #2 V1 合同测试另立 PR,与本实验目录无关。

## 6. Exit 判据(对齐 #2 原文)

- **GO**:参与人愿意使用纠错入口且恢复收益可观察(建议门槛,非行业基准:`recover_success ≥ 15/20`、`t_recover_ms` 中位数 ≤ 60s、`mispress_found = 0`、收尾访谈正面)→ 申请 #2 V1 生产立项(新增 `location_confirmed_at` + `uncertain` 状态,另行授权)。
- **ADJUST**:恢复路径只在部分品类有效(如稳定物)→ 收窄交互或品类,不扩建追踪设施。
- **STOP**:反馈本身造成额外成本、无实际修正价值 → 保留 #1 手动更新与「上次确认」展示,双钮不立项。
