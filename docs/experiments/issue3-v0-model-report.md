## 术语:A/B/C 指什么(全文沿用 issue #3 定义)

- **A 基线**:逐件语音录入(issue #1 / PR #2 已有链路),**不调用任何视觉模型**,不在本报告调用量估算内;
- **B 方案**:同一区域单张照片 → 视觉模型 → 多物品候选;
- **C 方案**:同一区域短视频 → ffmpeg 抽关键帧 → 多图输入 → 跨帧去重候选。

B/C 各对应「每区域 1 次模型请求」(见 §六请求划分)。

## 一、智谱 BigModel(GLM 系)

### API 形态

OpenAI Chat Completions 风格兼容。endpoint:`https://open.bigmodel.cn/api/paas/v4/chat/completions`,请求体为 `messages`/`temperature`/`stream` 等字段,鉴权为标准 HTTP Bearer(密钥在 bigmodel.cn 控制台「API Keys」页获取)。来源:[GLM-4.5V 模型页](https://docs.bigmodel.cn/cn/guide/models/vlm/glm-4.5v)、[对话补全 API 参考(securitySchemes: bearerAuth)](https://docs.bigmodel.cn/api-reference/%E6%A8%A1%E5%9E%8B-api/%E5%AF%B9%E8%AF%9D%E8%A1%A5%E5%85%A8.md)。

| 项 | 数值 |
|---|---|
| 支持格式 | `jpg`、`png`、`jpeg` |
| 单张大小 | 5M 以下 |

来源:[对话补全 API 参考](https://docs.bigmodel.cn/api-reference/%E6%A8%A1%E5%9E%8B-api/%E5%AF%B9%E8%AF%9D%E8%A1%A5%E5%85%A8.md)、[费用问题 FAQ](https://docs.bigmodel.cn/cn/faq/fee-issues.md)(2026-10-10 抓取)。

**关于 GLM-4.6V-Flash 变体规格的两点歧义(评审指出,如实记录,均列为探针验证点):**

1. **多图上限是否随本体**:API 参考的 50 张档写的是「GLM-5.3-Flash **系列**、GLM-5V-Turbo、GLM4.6V、GLM4.5V **系列**」——「GLM4.6V」一条未注明「系列」或「含 -Flash 变体」(对比:GLM-4V 本体与 GLM-4V-Flash 在同表中就是分开的两档 50/1 张)。**GLM-4.6V-Flash 的多图上限未单独列明,本文不把它断言为 50 张**;V0 请求设计按 ≤8 帧/请求(§六),即使该变体实际只有更低下限也有余量,最坏退化为逐帧单图请求+程序内合并候选(成本 ×8,见 §六)。
2. **是否支持 Base64**:API 参考只点名 GLM-4V-Flash 不支持 Base64,未排除 4.6V-Flash → 推定支持,由探针首次调用直接验证(探针即用 Base64)。

**上下文窗口**:模型概览页给出 GLM-4.6V(本体)上下文 128K、最大输出 32K;**GLM-4.6V-Flash 的上下文官方未单列**(开源模型卡称 GLM-4.6V 系上下文可达 128K,API 侧 Flash 变体未确认)。V0 单请求按官方 FAQ 单图 ≈1047 tokens 口径估算 ≈ 8 帧×1047 + 提示 500 ≈ **8.9k tokens**,低于同系列已知最低档(GLM-4V-Flash 16K),上下文风险低;探针以实测 token 回填。来源:[模型概览](https://docs.bigmodel.cn/cn/guide/start/model-overview.md)、[HuggingFace GLM-4.6V 模型卡](https://huggingface.co/zai-org/GLM-4.6V)。

### 视频输入规格

来源:同上(对话补全 API 参考)。200M 档是否含 4.6V-Flash 与多图同理存在「未注明系列」歧义;V0 不走原生视频输入,不受影响。即:**GLM 系支持原生视频文件输入,但 V0 仍按 issue 合同走「ffmpeg 抽帧→多图输入」,原生视频输入可作附加对照**。

## 二、阿里云百炼 Model Studio(Qwen 系)

## 六、V0 调用量、请求划分与预算上限(评审补充)

### 请求划分规则(先定规则才能数请求)

1. **每区域 × 每媒介 = 1 个请求**:B 方案单区域 1 张照片 1 请求(增拍则每张 1 请求);C 方案单区域人工剔选后 ≤8 帧合 1 请求。
2. **禁止跨区域合并**(如 3 区域 24 帧合一个请求):①issue #3 合同第 4 条「镜头跨不同区域时不自动绑定到同一位置」——位置上下文按区域隔离,跨区域合帧会制造错误位置归属;②对照计量按区域/媒介统计,合并破坏口径;③≤8 帧/请求远低于两家多图上限,即使 GLM-4.6V-Flash 实际多图上限是最低档(1 张,即 GLM-4V-Flash 情形),退化为逐帧 8 个单图请求 + 程序内合并候选,成本 ×8 仍在预算内。
3. A 基线(逐件语音)不调用视觉模型。

### 调用量与 token 估算(标注:除注明外均为按官方公式/口径的推算,非实测)

- 请求数:3 区域 × (B 1 + C 1) × 重复 R=3 = **18 次** + 探针验证 ~5 次 + 重试余量 ~50% ≈ **35 次**封顶。
- Qwen 侧单请求 token:8 帧(默认 max_pixels 2,621,440 封顶 → ≤2560 token/帧)+ 提示词 ~500 + 输出 ~1500(候选 JSON)≈ **22.5k tokens**;35 请求 ≈ **79 万 tokens** → **100 万免费额度内**(90 天有效期)。若免费耗尽走 qwen3.7-flash ≤32K 档:输入 ~0.74M×0.2 + 输出 ~0.05M×0.8 ≈ **0.19 元**。
- 智谱侧:GLM-4.6V-Flash 免费,**¥0**;token 量级按费用 FAQ「GLM-4V 系单图 ≈1047 tokens」口径:8 帧+提示 ≈ 8.9k/请求(旧代际口径,仅供量级)。若全部 35 请求走付费兜底 GLM-5.3-Flash(0.8/2.8 元/M):输入 ~0.31M×0.8 + 输出 ~0.05M×2.8 ≈ **0.4 元**。
- **预算硬帽:单一服务商 ≤ ¥5**(本报告设定的实验纪律,非平台限制)。执行方式:免费模型优先;付费档只在质量切换门触发后使用;**每次实验日结束核对控制台账单一次**(智谱/阿里控制台的消费告警功能未验证,不依赖)。达到 ¥5 即停,评估后再继续。按上述推算,实际支出预计 <¥1。

## 七、抽帧与压缩参数设计(评审补充,与两家硬限制对齐)

| 参数 | 取值 | 依据 |
|---|---|---|
| 固定间隔 | `--interval 2`(秒) | issue #3 增补 D:「3–8 张代表性关键帧」预算下,10–15s 慢扫视频 2s 间隔 ≈ 5–8 帧 |
| 场景切换阈值 | `--scene 0.3` | ffmpeg `select='gt(scene,T)'` 常用值;实测 12s 合成视频(testsrc→smptebars 硬切)在 0.3 命中 1 帧(本仓库 V0 骨架验证记录) |
| 帧数预算 | `--max 8`(人工剔选后 3–8) | issue #3 增补 D 示例预算 |
| 长边缩放 | `--scale 2048`(等比,竖拍视频限制的是长边) | 满足智谱 ≤6000×6000 与 ≤5M/张;Qwen 侧超过默认 max_pixels 会自动缩放、token 封顶 2560/帧,成本无影响,预缩放只省上传体积 |
| JPEG 质量 | `-q:v 2` | ffmpeg 高质量档;实测 1920×1080 合成帧缩至 2048×1152 后单帧 140–150KB(真实照片细节更多,预计 200–500KB/帧) |

请求体校验:8 帧 × ≤500KB × 1.33(Base64 膨胀)≈ **≤5.3MB** < Qwen 请求体上限 64MB;单张 <5M 满足智谱单张上限。结论:**默认参数下两家硬限制全部满足,无需额外压缩步骤**。脚本:`scripts/experiments/v0-visual/extract-frames.sh --interval 2 --scene 0.3 --max 8 --scale 2048`。

本节参数的实测记录(2026-10-10,合成视频,脚本 `extract-frames.sh` 当前版本):4K 横拍 3840×2160 → 帧缩为 2048×1152;竖拍 1080×1920 场景切换视频 → 5 间隔帧 + 1 场景帧,长边未超 2048 不放大;`--scale 0` → 3840×2160 原样输出;竖拍 yuv420p 输入曾触发 mjpeg 编码器「Non full-range YUV is non-standard」报错,已在脚本 filter 末尾加 `format=yuvj420p` 修复并复测通过。

## 十一、选型建议(v2 修订)

**主选:智谱 BigModel,V0 主跑 GLM-4.6V-Flash(免费),兜底 GLM-5.3-Flash(输入 0.8/输出 2.8 元/百万 tokens)。附一个前置条件:若 §八智谱条款书面确认无法排除训练用途、且实验者不接受,则主跑切阿里(次选升主选),智谱只跑合成图。**

理由:

1. **免费模型覆盖 V0 全程**:3 区域 × B/C × 3 重复 ≈ 18 请求 + 探针 ≈ 35 次封顶(§六),GLM-4.6V-Flash 输入/输出免费,预算帽 ¥5 内实际 ¥0;
2. **API 形态与现有代码同构**:`open.bigmodel.cn/api/paas/v4/chat/completions` 是 OpenAI chat/completions 形状,与仓库现有 DeepSeek 调用(`cloudfunctions/extractDraft/lib/deepseek.js` 同为 chat/completions)迁移面最小;
3. **硬限制数字齐全**:格式/单张 5M/6000×6000/50 张(4.6V-Flash 变体歧义已单列验证点),§七默认参数全部满足;
4. 质量面(§五):免费 9B 档官方 benchmark 位于第一梯队但**计数是自述弱项**,故质量切换门(§十)是流程的一部分,不是可选项。

**次选(对照与备胎):阿里百炼,默认对照模型从 v1 的 qwen3.8-flash 修订为 qwen3.7-flash。**评审指出 v1 未解释为何不用便宜 4 倍的 3.7-flash——接受修订,理由:①V0 单请求 ≈22.5k tokens,落在 3.7-flash 第一档(≤32K,0.2/0.8 元),价格 3.8-flash(0.8/2.7)的 1/4~1/3;②限流是两家唯一有公开数字的:北京 30,000 RPM / 5,000,000 TPM;③100 万 token×90 天免费额度同样覆盖全部调用量;④「更新代际=更好」没有 flash 档质量证据支持(§五只有 3.8-max 的第三方数据)。**qwen3.8-flash 保留为质量优先备选**(若门 1 触发且 3.7-flash 复测仍差,或需要原生视频输入对照时启用,注意其北京限流为动态档)。

**GLM-4.1V-Thinking-Flash(免费)不进主对照的理由**:thinking 变体先生成思维链再给答案,输出更长、响应更慢,直接拖累 V0 记录项「模型调用耗时」并使 B/C 对照混入推理时延变量;且为上一代模型(4.1V)。保留为门 1 触发后的第三免费备选。

**不建议 V0 采用:腾讯混元 vision。**三个原因:原生接口 2026-12-21 预下线、平台迁移期「不再新增模型能力、停止支持新购」;图片大小/数量限制无官方数字,违背 issue「先验证真实视觉输入规格」的合同精神;同档价格(3/9 元)约为另两家低价档的 4–15 倍。待 TokenHub 迁移稳定后可重新评估。

**视频路线备注**:三家都支持原生视频输入,但 issue #3 V0 合同明确「视频=关键帧抽取→多图理解→候选去重」,故 V0 统一走 ffmpeg 抽帧(`extract-frames.sh`),原生视频输入仅在抽帧方案失效时作附加对照(qwen3.8 系 2h/2GB 为最宽)。
