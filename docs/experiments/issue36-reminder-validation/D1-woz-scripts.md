# D1 Wizard-of-Oz 可交互脚本(A/B/C + 对照组)与记录模板(issue #36 研究件)

> 定位:issue #36 §7 交付件 D1。**不编码、不新增生产 schema、不动 miniprogram/ 与 cloudfunctions/**;「AI 识别」由研究员按本文脚本与 D1b 日期纪律人工模拟(Wizard-of-Oz),人工延迟如实记录,绝不美化为产品能力。
> 三切片对齐 #36 §2:A「说一次,未来找得着也记得换」/ B「拍包装少打字」/ C「完成一次维护自动备下次」;对照组 D 用「手机提醒事项 + 备注位置」做反证(#36 §1:不要只与空白对照)。

## 0. 通用纪律(所有切片生效)

1. **候选全部待确认**:界面呈现的物品/位置/日期/是否循环一律带「待确认」标记;保存按钮在用户逐项过目并确认前不可用。
2. **日期纪律**(细则见 D1b §2):相对周期必须明示基准日(录入日或完成日);未明示周期**不擅自循环**;无明确日期 → `need_confirm`,绝不静默猜测;月精度表达(「保修到 2027 年 3 月」)只给月份候选,日由用户选;药品/医疗类不提供提醒候选,只走位置记录。
3. **位置是「上次确认位置」**:兑现页展示的位置必须带确认时间戳,文案固定为「上次确认位置(YYYY-MM-DD 确认)」,不得写成「现在的位置」。
4. **人工提醒声明**:试验期内的提醒由研究员经用户同意的既有渠道(微信消息/电话)人工送达,话术与兑现页一致;严禁表述为「小程序会推送通知」。
5. **录入来源标注**:每条录入必填 `entry_source`:真实主动 / 研究员提示 / 研究员代录 / 体验任务强制(D1 §7)。

## 1. Wizard 配置(试验台)

- **道具**:候选模板卡(打印 A5 或分屏表格,字段=物品/位置/事项/日期候选+规则注/是否循环,全字段带「待确认」徽标)、兑现页卡、计时器(手机秒表或表格打点)、录音设备(经同意)。
- **模拟规则**:研究员现场按 D1b 的提取规则把用户原话转成候选,日期计算只在 D1b 规则允许时给出;遇到规则外表达(如新模糊词)一律走 `need_confirm`,不得现场发明日期。研究员每笔人工延迟记入 `t_extract_ms` 并标 `wizard_manual=true`。
- **语音路径**:优先用现有 PR2 语音链路真实转写;不可用时研究员听写原文,并记 `asr_mode=wizard_transcribe`。两条路径的数据分开统计,不混合。
- **任务来源**:E0 访谈收尾时用户自选 1-3 个真实未来事项(尽量 7-14 天内会发生);体验任务(为演示完整流程而设的虚拟事项)必须标 `task_real=false`,不进入真实行为统计。

## 2. 切片 A:说一次,未来找得着也记得换(#36 §2 优先级最高)

**示例任务**:用户真实事项「净水器备用滤芯在厨房水槽下面的柜子里,半年后提醒我换」。

### A-S1 录入页

- 界面:现有首页「记一件」,提示语扩展为:「一句话说清东西在哪、什么时候要做什么。例:备用滤芯在厨下柜,半年后提醒我换。」
- 用户动作:按住说话(或打字)→ 松开。
- 打点:`t_asr_ms`(按住→转写回显)/ 文字路径 `t_typing_ms`。

### A-S2 转写回显页

- 界面:整句原话 + 「重新说 / 就用这句」。
- 分支:用户改口重来 → 回 A-S1,重打点(记 `restart_count`)。

### A-S3 候选预览页(核心屏)

- 界面(全部字段带「待确认」徽标):

```
┌ 记住这件事(请逐项确认)
│ 物品:净水器备用滤芯            [待确认][改]
│ 位置:厨房水槽下面的柜子里      [待确认][改]
│ 事项:更换                      [待确认][改]
│ 提醒:2027-04-13(周二)       [待确认][改]
│   为什么:你说「半年后」→ 从今天(2026-10-13)起算 6 个月
│   ↳ 基准想用别的日子? [改基准日]
│ 重复:不循环(你未提到周期)    [待确认][改:每 X 月/年]
│ 出处:「半年后提醒我换」(原话引用)
└ [全部确认,保存]  [只记位置,不要提醒]
```

- Wizard:按 D1b 规则填卡;「半年后」= 录入日 +6 月且必须亮出基准日;用户原话里的限定语(「备用」「下面的」)保留在字段中。
- 打点:`t_extract_ms`(提交→本屏呈现,含人工延迟)。
- 追问(研究员口头,不计入操作):「日期这块,是你想的那样吗?」——只确认,不引导。

### A-S4 纠错分支(任一字段「改」)

| 触发 | 界面行为 | 记录 |
| --- | --- | --- |
| 改物品名/位置 | 键盘改写,或从「我的家」位置树选节点 | `corrections.item_name/location` +1 |
| 改日期 | 弹候选:今天+N 天/N 月(带基准说明)/ 日历手选/直接输入 | `corrections.date` +1;若改基准日,记 `base_changed=true` |
| 改重复 | 开关:不循环/每月/每季/每半年/每年/自定义 | `corrections.repeat` +1 |
| 「只记位置」 | 落回现有纯位置确认流程(不产生提醒) | `reminder_dropped=true` + 原因码 |
| 用户说「上次其实是 10 月 1 号换的」 | 基准日切为用户给定日,候选日重算并**重新明示新基准** | `base_source=user_stated` |

- 打点:`t_review_edit_ms`(本屏呈现→第一次主确认)、`t_correction_total_ms`(所有纠错累计)。

### A-S5 保存回执页

- 界面:「已记住:净水器备用滤芯 · 厨房水槽下面的柜子里;2027-04-13 会提醒你更换(不循环)。到时会带上这个位置。」
- 打点:`t_save_ms`;首条组合记录总耗时 `t_total_s` = 任务开始→本屏出现。

### A-S6 提醒兑现页(数日后,时间跳跃)

- 送达:研究员经约定渠道发送与下页一致的话术(标 `wizard_delivered=true`)。
- 界面:

```
┌ 该换净水器滤芯了
│ 上次确认位置:厨房水槽下面的柜子里(2026-10-13 确认)
│ ※ 位置可能已移动,以现场为准
│ [完成了]  [延期]  [停用]
```

- 分支:完成 → A-S7;延期 → 选新日期 + 原因码(没空/还没买耗材/其他+原话),记 `action=snoozed_correct|snoozed_wrong`;停用 → 原因码(不再需要/已丢弃/提醒太吵/其他),记 `action=disabled`。
- 行为记录:`action_taken`、用户是否按位置直达物品(`location_helped` bool + 备注)、若位置错了记错在哪。

### A-S7 完成 → 建议下次

- 界面:「已完成,记于 2027-04-14(如不是今天请改)。下次:从**完成日**起 6 个月后(2027-10-14)再提醒?[确认 / 改日期 / 不再提醒]」
- 纪律:完成日可改(防误点);**基准=完成日且必须明示**;单次提醒(未设周期)完成时明示「你没有设置重复,要安排下一次吗?」由用户输入,不自动猜;确认继续后物品**无需重录**。
- 幂等演示:重复点「已完成」只出现一次下次建议。

## 3. 切片 B:拍下有日期的包装,减少日期打字(#36 §2 次优先)

**示例任务**:常温奶整箱(生产日期 + 保质期)或保修卡;药品/医疗类包装不入选(S8 排除)。

### B-S1 拍照页

- 界面:「拍一张能看到日期的包装(正面朝上,日期区域别反光)。」
- 打点:`t_capture_ms`(含重拍;`retake_count` 记数)。

### B-S2 候选溯源页(核心屏)

- 界面:照片预览,每个候选**在照片上有高亮框**:

```
┌ 从这张包装上看到(请逐项核实):
│ 品名:全脂牛奶 250ml×16        [高亮:箱体正面][待确认]
│ 生产日期:2026-10-05           [高亮:侧面喷码][待确认]
│ 保质期:6 个月                  [高亮:侧面喷码][待确认]
│ (没有直接印「有效期至」)
└ [就用这些]  [框选错了,我来改]
```

- 纪律:候选**只来自图上可见内容**且可点高亮回溯;「有效期至/生产日期/批号」三类标签不得互换;图上没有的字段不出现在候选中。
- 打点:`t_ocr_ms`(拍照→本屏;人工模拟如实记延迟)。

### B-S3 位置补充页(必经)

- 界面:「照片只能告诉我们日期。这件东西放在哪?」→ 一句话或位置树选择。
- 记录:位置来源=用户陈述(照片不证明位置,#36 §2 风险)。

### B-S4 换算确认页

- 界面:「按 生产日期 2026-10-05 + 保质期 6 个月 → 建议提醒 2027-04-05(提前几天?)[到期当天 / 前 3 天 / 自选]。请确认。」
- 分支:包装直接印「有效期至」→ 跳过换算,直给候选;用户指出框错(如把批号当日期)→ 改候选或手输,记 `corrections.date` + `ocr_misread=true`。

### B-S5/B-S6

- 保存回执与兑现页同 A-S5/A-S6(位置来自 B-S3)。
- 打点分解:`t_capture_ms / t_ocr_ms / t_verify_edit_ms / t_location_ms / t_save_ms`;与研究问题对齐:**是否真的少打字、少纠错要看端到端净收益,不以 OCR 成功率代替**(#36 §3 P1)。

## 4. 切片 C:完成一次维护,自动准备下次

从真实兑现页出发(可与 A 的 A-S6 同一条提醒复用)。

### C-S1 → C-S2 完成确认页

- 界面:「已完成,记于 2027-04-14。是今天吗?[是 / 改日期]」(防误点;误点可撤回,撤回记 `undo_count`)。

### C-S3 下次候选页

- 界面分两型:
  - 有已确认周期:「按你确认过的每 6 个月 → 下次 2027-10-14(从完成日起算)。[继续 / 改 / 停止]」
  - 无周期(单次):「你没有设置重复。要为它安排下一次吗?[设一个 / 不用了]」——**不自动猜周期**(#36 §2 风险:周期变化/停止使用)。
- 分支:周期变化(换型号,滤芯周期改 12 个月)→ 用户改,记 `period_changed=true`;停止使用 → 停用 + 原因码。

### C-S4 保存

- 「已安排:2027-10-14 再提醒(物品与位置沿用,无需重录)。」

## 5. 对照组 D:手机提醒事项 + 备注位置(反证组)

同一用户、难度接近的真实任务,用**其本人手机**的系统工具完成(#36 §1:与替代方案对照,不只与空白对照)。iOS 步骤如下(Android 各厂商 App 步骤由研究员现场照实记录,行为差异标「未核实」):

| 步 | 操作(iOS 提醒事项,官方支持口径) | 打点 |
| --- | --- | --- |
| D-1 | 打开「提醒事项」,新建提醒 | `t_open_ms` |
| D-2 | 输入标题(如「换净水器滤芯」) | `t_title_ms` |
| D-3 | 编辑详细信息 → 备注 → 输入位置(如「厨下柜」) | `t_note_ms` |
| D-4 | 打开「日期」→ 日历翻到目标日 | `t_date_ms`(记翻页月数) |
| D-5 | (可选)设置「重复」 | `t_repeat_ms` |
| D-6 | 回列表确认已存在 | `t_verify_ms` |

来源:[在 iPhone 上的「提醒事项」中添加详细信息](https://support.apple.com/zh-cn/guide/iphone/iphec7a1de82/ios)、[使用「提醒事项」](https://support.apple.com/zh-cn/102484)。

- **兑现演练**(数日后同样人工送达):通知到达 → 用户看到标题与备注 → 研究员问:「东西在哪?你怎么知道的?」——记录用户是否需要回忆、备注是否够用、找不到时的策略。
- 对照问题(口头):「如果半年后你忘了『厨下柜』是什么意思,这个提醒还能帮到你吗?」(如实记录,不引导。)

## 6. 任务分配与顺序

- 每户:A(必做)、D(必做)、B/C 择一(有真实包装任务选 B,有真实到期事件选 C);顺序轮换(A→D 与 D→A 各半)以抵消学习效应。
- 同一用户的 A/D 任务尽量同难度(同类物品、同类周期)。
- 样本小(10-15 户):**仅供机制发现,禁止宣称统计显著性**;只报告原始数、中位数与逐案例描述。

## 7. 耗时 / 纠错记录模板(对齐 #36 §5 指标)

### 7.1 CSV 字段定义(一行 = 一次切片任务)

| 字段 | 类型/枚举 | 说明 |
| --- | --- | --- |
| `session_id` / `household_anon_id` | 字符串 | 匿名 id(D2 §1 规则) |
| `slice` | A/B/C/D | 切片 |
| `task_desc_anon` | 字符串 | 匿名化任务描述(不含人名/地址) |
| `task_real` | bool | 真实未来事项 vs 体验演示任务 |
| `entry_source` | self_initiated / researcher_prompted / researcher_entered / task_forced | 录入来源标注(#36 §4,分母不混淆) |
| `t_asr_ms` / `t_typing_ms` | 数值 | 语音(按住→回显)或打字耗时,二选一记录 |
| `asr_mode` | real_pipeline / wizard_transcribe | 真实链路 or 研究员听写 |
| `t_extract_ms` | 数值 | 提交→候选呈现;`wizard_manual=true` 必标 |
| `wizard_manual` | bool | 本条是否人工模拟 |
| `t_review_edit_ms` | 数值 | 候选呈现→第一次主确认 |
| `t_correction_total_ms` | 数值 | 纠错动作累计耗时 |
| `t_save_ms` | 数值 | 主确认→保存回执 |
| `t_total_s` | 数值 | **首条组合记录总耗时**(任务开始→保存回执;§5 口径 p50 目标 ≤30 秒,指此字段) |
| `restart_count` | 整数 | 重说/重拍次数 |
| `extra_confirm_count` | 整数 | 首次主确认之外的逐字段确认次数(§5「≤1 次额外明确确认」用) |
| `corrections.item_name` / `.location` / `.date` / `.repeat` / `.kind` | 整数 | 分字段纠错数 |
| `correction_type` | fix_error / rephrase / disambiguate | 纠错性质抽样标注 |
| `base_changed` / `base_source` | bool / wizard_rule / user_stated | 日期基准是否被用户改 |
| `reminder_dropped` | bool + 原因码 | 「只记位置不要提醒」分支 |
| `abandon` + `abandon_reason` | bool + too_slow / distrust_candidate / interruption_aversion / privacy / other_quote | 放弃与原因(#36 §4 E1) |
| 兑现段:`reminder_due_date` / `wizard_delivered` / `action_taken` | 日期 / bool / completed / snoozed_correct / snoozed_wrong / disabled / no_action | 真实到期才填 |
| `location_helped` + 备注 | bool / 文本 | 位置是否帮助直达物品 |
| `location_wrong_note` | 文本 | 位置失效案例(错在哪、用户怎么补救) |
| `negative_notes` | 文本 | 负面案例自由字段 |

### 7.3 统计与报告口径

- §5「首条组合记录耗时」= `t_total_s`;分解字段只作归因,不替代总口径。
- n<30 时只报告原始数与中位数;**所有人工模拟延迟不得剔除**,并在表头标注 `wizard_manual` 占比。
- 与对照组 D 的比较按同用户配对呈现(每人 A vs D 的 Δ步骤、Δ耗时、Δ纠错),不做显著性检验。
