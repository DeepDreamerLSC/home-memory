# 个人入口与主题设置提案

状态：HTML原型已确认，原生小程序代码已实现。延续 `../ui-polish-v1/` 与根目录 `DESIGN.md` 的已确认风格。实现范围、原生验证和云端部署边界见 `IMPLEMENTATION.md`。

## 设计前的实现事实（原型基线）

- 首页内容区右上是家庭入口，没有头像入口：`miniprogram/pages/index/index.wxml:8`。当前没有页面使用 `chooseAvatar`、`input type="nickname"`，也没有调用 `updateHouseholdProfile()` 的页面。因此没有完整的头像选择、上传和昵称编辑路径。
- 共享家庭成员列表仍展示历史头像与昵称；缺失时显示“我/成员”等占位：`miniprogram/pages/family/family.wxml:111`。
- `updateHouseholdProfile()` 和 `households.updateProfile` 尚在：`miniprogram/utils/households-api.ts:527`、`cloudfunctions/households/lib/handler.js:269`。它只允许共享家庭，并只修改本人在当前 `household_members` 中的会员行；不是全局个人资料。
- `households.status` 在个人家庭返回空头像昵称，在共享家庭返回自己的会员资料：服务端同文件319–345行。客户端展示缓存是 `home-memory:self-nick` / `home-memory:self-avatar`，切换家庭会清空后重读：`miniprogram/utils/household-scope.ts:320`、`miniprogram/utils/households-api.ts:134`。
- 当前外观跟随系统深浅色：`miniprogram/app.json`、`miniprogram/theme.json`、`miniprogram/app.wxss`；没有用户选择配色或手动明暗的设置和持久化。

这些事实说明：前端可以增加固定入口，但把现有共享家庭缓存直接用于永久个人头像，会出现切家后头像消失的问题。

## 原型里的体验

1. 首页内容标题右侧放44px头像入口，不占用微信原生胶囊。家庭入口下移到计数同行，仍可直接切家。
2. 点击头像进入“我的”：头像昵称编辑、主题配色、首页显示、家庭入口。
3. 主题提供奶油、苔绿、雾蓝、陶土四套柔和配色，以及墨金、钴蓝、翠绿、莓红四套鲜明配色；每套支持跟随系统、浅色、深色。预览同时改变底色、文字、按钮和插画，用户可进入实际首页预览。点击应用才保留，直接返回会还原已保存主题。
4. 首页显示可单独关闭最近记录和到期提示。关闭提示不取消提醒、不删除记录；页面保留这个解释。
5. 头像与昵称使用示例内容，资料保存后回显；空昵称不能保存。所有演示偏好只写本浏览器的独立原型存储键，不读写微信数据。

本版先提供整套配色，不开放任意色值。这样能同时保证文字可读性、插画协调和深色模式，避免用户选了喜欢的颜色后看不清按钮。没有加入字体、背景图片、任意拖拽布局等额外配置。

## 建议的实际实现顺序

1. **先恢复稳定入口与身份。** 用户主动选择头像、填写昵称；不在进入首页时强制填写。没有资料时使用默认人像，设置仍可使用。微信官方维护的[头像昵称组件资料](https://github.com/wechat-miniprogram/mp-user-avatar)说明了 `chooseAvatar` 与 `nickname` 输入能力；这里参考交互方式，不引入该已归档组件依赖。
2. **明确资料归属。** 个人入口需要独立于家庭的用户级资料，允许个人家庭用户保存。复用现有昵称校验、服务端本人身份派生及缓存模式，但不能直接复用仅共享态可写的会员记录作为账号记录。保留既有家庭成员资料；是否用新全局资料覆盖成员列表显示需要单独确定迁移规则，不能静默批量覆盖。
3. **增加个人外观偏好。** 首版在本机按当前用户保存配色、明暗和首页显示配置，不按家庭清空；所有页面和共享组件读取同一份主题状态。跨设备同步可以在用户级偏好接口稳定后增加。主题切换需要同步处理页面颜色、原生导航、背景、深浅插画和共享组件，不能只改首页CSS。
4. **验证范围。** 覆盖无头像、个人家庭、共享家庭、切家、冷启动、恢复默认、系统明暗变化、手动明暗覆盖，以及关闭首页提示后提醒行为不变。实际头像上传和昵称快速填充必须真机验证。
