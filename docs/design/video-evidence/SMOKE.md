# Video Evidence 本地冒烟记录

**日期**:2026-10-19
**范围**:验证「原视频 -> 均匀抽帧 -> 逐帧视觉模型 -> 同名聚合 -> 时间窗/框」链路中的真实模型段。
**边界**:本地模型、本地素材、零外部上传;不包含微信真机抽帧、上传、播放与高亮叠加验证。

## 方法

- 素材:项目既有探索样片 1 段,时长约 46.2s;公开记录不附视频与物品名。
- 抽帧:取 5%–95% 时长均匀 8 点,ffmpeg 单帧导出,长边压到 ≤1024、JPEG q3。
- 模型:本地 `127.0.0.1:8307`,Qwen3-VL-8B-Instruct-4bit,temperature 0.1,max_tokens 2000。
- 调用:每帧单独请求,共 8 次;每次请求 1 张图 + 生产风格识物提示。
- 聚合:调用仓库内 `aggregateVideoRecognitions`(同名精确归并,保留逐帧时间窗与 0-1 框),最多保留 10 个候选。

## 结果(脱敏)

| 指标 | 结果 |
|---|---|
| 模型调用 | 8 次 |
| 成功帧 | 8/8 |
| 总推理耗时 | 38.67s |
| 平均每帧耗时 | 4.83s |
| 原始候选条目 | 55 |
| 带有效 0-1000 框的条目 | 55/55 |
| 精确同名去重后条目 | 39 |
| 最终展示候选(上限 10) | 10 |
| 跨帧重复出现的候选 | 8/10 |
| 最大跨帧出现次数 | 3 |
| 生成高亮时间窗 | 23 |

## 观察与限制

1. 8/8 帧返回合法 JSON,0-1000 框全部可归一,说明「逐帧识别 -> 证据框」基础链路可用。
2. 平均约 4.8s/帧;8 帧串行时仅模型段约 39s,还没算抽帧、base64 传输与保存。真机体验需要按设备和网络重测,并考虑并发/降级。
3. 同名精确聚合会把同义名拆开(如「充电器/充电线/USB 数据线」),也会误把非物品标签保留;39 个精确名截到 10 个可能漏掉真实物品。这是当前候选层的主要质量缺口,需要后续做同义词归一/非物品过滤/更可靠的跨帧身份策略。
4. 本冒烟只证明本地模型 JSON 输出和聚合数据结构可跑通,**不能证明**微信端 `createVideoDecoder` 抽帧成功、视频上传/播放成功、自动播放策略可用、高亮框与播放时间在实际 UI 中对齐。
5. 不改变 #85 S2 的 STOP 结论;本功能的核心价值仍是「查找时能翻出并回放视频证据」,自动识物是增强层,候选必须由用户确认。
