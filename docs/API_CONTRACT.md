# API 契约(home-memory PR1 文字闭环 + issue #18 Location Tree)

## 产品与范围
用户用一句话记录物品位置(如「降压药放在厨房第二个抽屉」),AI 提取草稿,用户确认后入库;之后按名称查询位置;可修改位置、删除。核心原则:AI 只生成待确认草稿,绝不直接写事实;不确定时禁止猜测;任何失败绝不静默写入。issue #18 起位置沉淀为可浏览的递归空间树(locations 集合 + pages/locations 浏览 + 生成向导),物品经挂载字段关联到树节点,原始 location_text 永不改写。

## 技术栈(固定)
微信原生小程序(TypeScript 预编译:改动 .ts 后 npm run build:mp 在源码旁产出同名 .js,.ts 与 .js 成对提交;不用 useCompilerPlugins,实测部分版本 CLI 构建不产出 JS)→ wx.cloud.callFunction → 微信云开发 Node.js 云函数(JavaScript CommonJS,除 wx-server-sdk 外零 npm 依赖)→ CloudBase 文档数据库,items 与 locations 两个集合。不引入 Redis、向量库、FastAPI、自研队列。DeepSeek API 仅服务端调用。

## 身份与隔离
云函数用 cloud.getWXContext().OPENID 取身份;客户端传来的 household_id/openid 一律忽略;itemsApi 与 locations 的 handler 不得从 event 读取任何身份字段,身份只来自 deps.householdId(由 index.js 解析,见下),缺失时返回 UNAUTHORIZED。所有读写都必须带服务端派生的 household_id 条件;跨家庭访问统一表现为 NOT_FOUND。README 需说明建议为 items 建 (household_id, operation_id) 唯一索引、为 locations 建 (household_id, parent_id, name_norm) 唯一索引;代码中先查后插 + E11000 回查实现幂等。items 增可空字段 location_node_id 且唯一写入方为 locations 函数,一切写入均为版本条件更新(见下)。

### 可信家庭解析与失败关闭(issue #34 P0+P1-A)
个人家庭 household_id = "hh_" + sha256(openid) 十六进制前 32 位(避免裸 openid 落库;存量算法不变)。家庭共享 v0 起,itemsApi 与 locations 两个函数族的 index.js 在进入 handler 前先经 `lib/household.js`(三份逐字节同源副本:itemsApi 源 + locations/households 副本,漂移由 tests/household.test.js HH-SRC 拦截)解析当前可信家庭,extractDraft/transcribe 为无状态服务,不引入本解析:

- 会员身份摘要 member_key = sha256(openid) 十六进制全文(服务端从可信 OPENID 派生,不持久化裸 openid);
- 查 active_household(member_key 唯一):明确无记录 → 确定性回退个人家庭(单人用户零感知);命中 → 三向验证(P1 硬门 A):①必须在 household_members 存在 (household_id, member_key) 会员行且 role 合法(孤儿指针 → 失败关闭);②households 元数据行存在且 dissolved === false、scope_revision 为正整数(已解散/缺行/字段非法 → 失败关闭——P0 只验会员行存在,不足以支撑移除/解散后的访问撤权);
- 任何查询异常(含集合未创建)、指针不唯一、指针字段非法 → 返回 HOUSEHOLD_UNAVAILABLE(中文 message 可直展示)并终止本次操作,绝不回退个人家庭继续读写(宁拒一次操作,不把任一家庭的数据错写进另一个家庭);
- 解析结果(纯函数,零写入):个人家庭 → { householdId, shared:false };共享家庭 → { householdId, shared:true, scopeRevision, role, displayName }。

数据集合(控制台人工创建,权限「所有用户不可读不可写」):household_members { household_id, member_key, role("owner"|"member"), joined_at, invited_by },组合唯一索引 (household_id, member_key);active_household { member_key, household_id, updated_at },唯一索引 (member_key);households(P1-A){ _id 即共享家庭 household_id("hh_f_"+随机 hex,与个人家庭 sha256 派生 id 不可混淆), display_name, dissolved, scope_revision, created_at, dissolved_at? },_id 天然唯一;household_invites(P1-A){ household_id, token_hash(sha256(裸令牌),裸令牌绝不落库), created_by, created_at, expires_at, revoked, revoked_at? },唯一索引 (token_hash)。

### F2 跨家庭写入绑定与 list 作用域字段(issue #34 P0+P1-A 写入硬门)
- itemsApi 的 create/update/delete/remindComplete/remindClear/remindSet(#36 提醒实体写操作,见「reminders 集合与提醒 action」)与 locations 的 ensurePath/rename/move/merge/delete/linkItem/unlinkItem/applyScan/ensureAndLink(写类 action)在进入业务逻辑前经 `lib/household.js` 的 checkWriteScopeBinding 统一裁定,**共享家庭(解析为 shared)硬门**:必须携带 `expected_household_id` 且与解析一致(缺失/不一致 → FAMILY_SWITCHED,零业务写入),且携带 `expected_scope_revision` 与 households.scope_revision 一致(缺失/不一致 → FAMILY_STALE_SCOPE,零业务写入;单调修订号挡成员变更/家庭切换后的旧请求误写与 A→B→A 的 ABA 重放);两 marker 类型非法 → INVALID_INPUT;
- **个人(单人)家庭维持 P0 宽松口径**:expected_household_id 可选(携带则校验,不一致 FAMILY_SWITCHED;非字符串 INVALID_INPUT),expected_scope_revision 无语义、一律忽略——0.4.7 及以前客户端单人零回归;
- 两参数仅做一致性前置校验,绝不授权:身份与家庭归属始终由服务端独立解析;旧客户端(不发 marker)在共享活跃态下写操作被受控阻断(FAMILY_SWITCHED),要求升级;
- itemsApi.list、itemsApi.remindList(#36)与 locations.list(仅这三个只读 action)响应携带 `household_id`(sha256 派生或共享家庭 id,非 PII;集合权限不变),共享家庭另携带 `scope_revision`(客户端写请求前捕获作用域+修订的来源),作为客户端家庭作用域捕获依据(缓存/草稿键隔离,见 miniprogram/utils/household-scope.ts)。

## items 集合文档
字段:_id(等于 "it_" 加服务端随机串)、household_id、name(去空白后 1-50 字)、name_norm、location_text(去空白后 1-200 字)、note(≤200,可空字符串)、version(从 1 起)、deleted(false)、operation_id(创建幂等键,非空 ≤64)、last_update_id(可选,最近一次带 update_id 的成功更新回写的标识,≤64)、last_update_fingerprint(可选,该次更新内容字段的稳定指纹:键排序 JSON 字符串,重放识别用)、created_at(ISO 字符串)、updated_at(ISO 字符串)、location_node_id(可空,issue #18 新增:挂载的 locations 节点 _id;缺失/null = 未挂载;指向不存在节点 = 悬挂,读侧按未挂载容忍。itemsApi 对该字段一律忽略、投影不含;唯一写入方是 locations 云函数,且一切写入均为「以读到的当前 version 为条件」的条件更新并 +1——与 itemsApi.update 完全同构的单一版本链,系统内不存在对 version 的无条件改写)。可选字段 remind_vague_quote(0.6.0 真机反馈 Fix 4,可空字符串):录入时「原话提到了时间但没换算」的逐字子串(如「半年后」),仅 itemsApi.create 写入(与 reminder 互斥:带合法 reminder 时存空串;校验宽松——非空 ≤200 码点短文本即可,非法按未携带存空串),存储只为详情页展示,**不产生任何提醒**;update 不改写它。所有面向客户端的响应只给投影字段 { item_id, name, location_text, note, version, updated_at },绝不包含内部字段;唯一例外是 **get(详情)投影额外携带 remind_vague_quote**(缺字段按空串兜底),query/list 投影零变化。

## normalizeName(s)
NFC 归一 → 全角转半角 → 小写 → 去所有空白字符 → 去中英文标点。name_norm 与查询词都经过它。

## itemsApi 协议
event 形如 { action, ... };统一响应 { ok:true, ... } 或 { ok:false, error:CODE, message(中文,可直接给用户看) }。错误码:INVALID_INPUT、NOT_FOUND、VERSION_CONFLICT、UNAUTHORIZED、OPERATION_CONFLICT、FAMILY_SWITCHED(写类 action 携带的 expected_household_id 与服务端解析不一致,或共享家庭缺该参数;issue #34 P0 F2 + P1-A 硬门)、FAMILY_STALE_SCOPE(共享家庭写类 action 的 expected_scope_revision 缺失或与 households.scope_revision 不一致,issue #34 P1-A)。index.js 解析家庭失败时返回 HOUSEHOLD_UNAVAILABLE(见「可信家庭解析与失败关闭」)。
- create:入参 { action:"create", operation_id, name, location_text, note?, remind_vague_quote? }(remind_vague_quote 为 0.6.0 真机反馈 Fix 4 的可选「说了时间但没换算」原话子串:宽松校验、与 reminder 互斥,见「items 集合文档」;0.6.0 起客户端确认页不再随 remindComplete 传 period_days,该参数与再生逻辑保留供 API 兼容)。校验:operation_id 非空 ≤64;name 去空白后 1-50;location_text 去空白后 1-200;note ≤200。校验失败返回 INVALID_INPUT 且绝不写入。**幂等只对「同键同内容」成立**:查 (household_id, operation_id, deleted:false) 已有——name/location_text/note 与本次一致则返回 { ok:true, item(投影), duplicated:true };内容不同则返回 { ok:false, error:"OPERATION_CONFLICT", message:"这条已保存过且内容与当前填写不同,请到详情页修改", existing(投影,已删时不下发) },绝不静默返回旧数据。并发下唯一索引拒绝第二笔插入时:捕获重复键错误后回查,按上述同款规则返回稳定结果(同内容 duplicated;异内容或命中已删文档 OPERATION_CONFLICT,已删变体 message 说明已删除)。新插入 version=1、deleted=false,返回 { ok:true, item(投影), duplicated:false }。可选 reminder 参数(issue #36)见「reminders 集合与提醒 action」。
- update:入参 { action:"update", item_id, expected_version, update_id?, location_text?, name?, note? }。update_id 可选(非空 ≤64),标识同一次逻辑修改,用于响应丢失后的重试重放。至少一个可变字段,字段校验同上。条件更新:where(_id 等于 item_id 且 household_id 匹配且 deleted 为 false 且 version 等于 expected_version)更新字段、version 加一、updated_at 刷新(name 变则 name_norm 重算;带 update_id 时回写 last_update_id 与 last_update_fingerprint——指纹只覆盖内容字段,不含版本元数据)。命中 1 条返回 { ok:true, item(投影) };命中 0 条再查该 _id 与 household_id 且未删:存在且**三重条件同时成立**(version 恰为 expected_version+1、last_update_id 等于本次 update_id、last_update_fingerprint 等于本次内容指纹)判定为「自己刚写入但响应丢失」的重放,返回 { ok:true, item(投影), replayed:true };相同 update_id 但内容不同一律 VERSION_CONFLICT,绝不把新内容当重放吞掉;其余存在即 VERSION_CONFLICT,不存在即 NOT_FOUND。
- delete:入参 { action:"delete", item_id }。条件更新 where(_id 且 household_id 且 deleted 为 false)置 deleted 为 true 并把 name、name_norm、location_text、note 全部抹成空字符串。返回 { ok:true };查无则 NOT_FOUND。查询与列表永远过滤 deleted 为 false。
- get:入参 { action:"get", item_id }。按 id 单查(where _id 且 household_id 且 deleted 为 false),返回 { ok:true, item(投影) };查无或越权均 NOT_FOUND。用于详情页冲突刷新等场景,不受 list 分页截断影响。
- query:入参 { action:"query", q }。q 去空白后非空否则 INVALID_INPUT。nq 为 normalizeName(q);按 name_norm 精确匹配优先、其次前缀匹配、最后包含匹配,各自按 updated_at 降序,合并去重,最多 20 条,返回 { ok:true, items:[{item_id,name,location_text,note,version,updated_at}], match_type:"exact" 或 "prefix" 或 "contains" 或 "none" }。无结果是正常结果(items 为空数组)。
- list:入参 { action:"list", limit? }。deleted 为 false,updated_at 降序,limit 默认 50、最大 50,返回 { ok:true, household_id(服务端解析的当前家庭,issue #34 P0), scope_revision(仅共享家庭,issue #34 P1-A), items:[同上] }。
- create/update/delete 的作用域绑定(issue #34 P0 F2 + P1-A 写入硬门,详见「F2 跨家庭写入绑定」):共享家庭必须携带一致的 expected_household_id + expected_scope_revision,否则 FAMILY_SWITCHED / FAMILY_STALE_SCOPE 且零写入;个人家庭维持宽松口径(expected_household_id 可选、expected_scope_revision 忽略)。
- 未知 action、缺必填字段一律 INVALID_INPUT。
- handler 是纯函数:handler(event, deps),deps = { db, now(), genId(), householdId, logger },依赖注入以便离线测试;index.js 只做 wx-server-sdk 胶水。logger 只输出 action、错误码、耗时、计数,绝不输出原文、身份、物品名、位置,也不输出提醒的日期明细。

## reminders 集合与提醒 action(issue #36 二阶段:独立提醒实体;PR #52 B1 增轮次号条件更新;二轮复审增每物品 slot 生命周期权威)
提醒是**独立 reminders 集合**,绝不把提醒字段堆到 items 文档上(items 文档形状与投影零变化)。两类文档:①提醒行:_id(PR #52 起 rg_/rh_/rs_ 三前缀 + item_id 与目标轮次确定性派生——rg_ 周期再生、rs_ 补录/改设、rh_ 首建与自愈(首建行同样确定性派生,与自愈孪生收敛;不再使用 rd_+随机串),并发同轮双插被集合 _id 唯一性拒绝后收敛)、household_id(服务端派生,口径同 items)、item_id(内部关联)、status("active" | "done")、generation(提醒轮次号,同一 item 内单调递增绝不重置,标识「用户看到的那一轮」;新写入行必有,首建为 1)、due_date(YYYY-MM-DD,真实日历日)、kind("有效期" | "开封后" | "下次维护",#36 冻结词表,与 extractDraft v2 的 remind_kind 同源)、quote(≤200 码点,可空字符串:原话锚定由客户端在确认页完成,create 时服务端没有原话可比对,故放宽子串校验、只做类型与长度校验;日期选择器来源的提醒本就没有 quote)、created_at(ISO)、completed_at(ISO,仅 done 行)、next_period_days/next_due(仅 done 行:周期完成时原子落账的「欠账再生」标记——再生插入失败时凭它治愈恢复,提醒被显式改设/清除后作废置 0);done 历史行允许累积(同一 item 多条 done 合法)。②**slot 生命周期权威文档**(PR #52 二轮复审 N1/N2/N3 收口):每物品一条,_id = "slot_"+item_id,status 固定 "slot"(与行查询的 active/done 过滤天然隔离,remindList 与级联清理永不误读误删),字段 rev(单调代际权威:已发行含预留的最大轮次号,只增不减,**硬清除提醒行后依然保留**——旧轮次号永不与新轮复用)+ pending_gen/pending_kind("create"|"regen"|"set")/pending_base_gen/pending_period_days/pending_due/pending_rd/pending_rk/pending_rq(跨操作共享的欠账/声明标记,pending_gen=0 为净空)。remindComplete/remindSet/create-追加 的每一次「发新轮」都先对 slot 做一次条件更新(CAS)认领目标轮次并登记欠账——这是 complete/set/clear **共享的线性化点**;行落地统一走「复核认领仍归本请求 → 确定性 _id 插入 → CAS 消费欠账;消费失败(如被 clear 抢先)→ 补偿删除自己刚落地的行并显式冲突」。remindClear 显式消费欠账并作废行上的历史标记。权限「所有用户不可读不可写」(控制台人工创建集合;部署清单见 README);集合除 _id 固有唯一性外**无业务唯一索引**——「每 item 至多一条 active、同一轮至多完成与再生一次」由 slot CAS + 行级轮次条件更新 + 确定性 _id 三层保证:并发/交错(deferred)请求恰有一个认领命中,孪生插入撞 _id 后回查收敛,认领被消费的在途落地自行补偿撤销。到期只在客户端列表页露出,产品无任何推送/通知承诺。

- **rename**:入参 { node_id, name }。校验存在、非 home 根(parent_id==="" 判根)、新名 1-30 码点、同级 name_norm 不重名(NODE_CONFLICT)。更新自身并把全部后代 path 级联重写;绝不碰 items(location_text 原始话语不变,挂载引用节点 id 不受影响)。返回 { ok:true, node }。
- **move**:入参 { node_id, new_parent_id }。校验两节点存在、双方非 home 根(判根同上)、new_parent 非自身及其后代(NODE_CONFLICT「不能移动到自己下面」)、新家同级不重名(NODE_CONFLICT)、移动后子树深度 ≤6(否则 INVALID_INPUT「层级太深了」)。parent_id 更新 + 子树 path 前缀整体重写,不碰 items。返回 { ok:true, node }。
- **merge**:入参 { source_node_id, target_node_id }。校验双方存在、source≠target、双方非 home 根(判根同上)、**纯结构深度规则(issue #30 PR A,替代「同 type 才能合并」)**——source 无直接子节点(叶子)时任意深度允许(跨层重复合并,issue #27);source 带直接子节点时须与 target 同深度(path.length 相等,跨深度 → INVALID_INPUT 引导先移动)、target 非 source 后代、双方直接子节点无 name_norm 重名(NODE_CONFLICT 附 clashing_names)。执行顺序:① 物品阶段——逐件条件重挂载到 target(version 条件更新 + 派生 last_update_id,0 命中回查:已挂 target/重放识别则视为完成,否则中止整单返回 VERSION_CONFLICT 附 detail:{ conflicted },已成功件保持、重试安全);② 后置校验循环直至 source 直接挂载物品清空;③ 结构阶段——source 直接子节点 parent_id 改指 target(id 不变,挂在后代上的物品零改动);④ 硬删 source + 补偿扫描摘除悬挂挂载(计入 compensated)。返回 { ok:true, node, remounted, compensated, compensated_skipped }。收敛语义:重试时已完成件识别跳过;source 已删则 { ok:true, detail:{ already_merged:true } }。
- **delete**:入参 { node_id, force? }。统计子树(自身+后代)未删物品数与后代节点数:force 缺省/false 时非空即 NODE_NOT_EMPTY(附 detail 计数);force=true 时子树仍有任何未删物品依旧 NODE_NOT_EMPTY(物品永远不能被结构操作丢弃),无物品的空分支整支硬删除。删除后补偿扫描:对被删节点 id 集合查悬挂挂载并逐件条件摘除(置 null、version+1、派生标识),计入 compensated,UI 如实展示。返回 { ok:true, deleted_nodes(含自身), compensated, compensated_skipped }。删后重建同名节点可行(硬删除语义)。
- **linkItem / unlinkItem**:入参 { item_id, node_id(仅 linkItem;非 home 根,判根同上)/-, expected_version(正整数), update_id(非空 ≤64,失败重试同内容复用) }。与 itemsApi.update 完全同构:条件更新 where(_id 且 household 且 deleted:false 且 version=expected_version)置 { location_node_id, version:+1, updated_at, last_update_id, last_update_fingerprint };命中返回 { ok:true, item:{ item_id, version, updated_at } };0 命中回查三重条件(版本恰为 expected+1、last_update_id 相同、指纹一致)成立返回 { ok:true, replayed:true, item },否则 VERSION_CONFLICT / NOT_FOUND。内部批量写入(merge 重挂/补偿摘除/applyScan)不用客户端 update_id,改用确定性派生标识 "<op>:" + sha256 前 16 hex(≤27 字符),同输入恒同值,是收敛式重试的前提。
- **ensureAndLink**(issue #45 十七轮「放进」,#18 红线语义升级):入参 { action:"ensureAndLink", item_id, path:[≥1 段且 1-6 段,每段去空白 1-30 码点,首段=房间/大区域(深度 1 节点)], expected_version(正整数), update_id(非空 ≤64), created_from?("scan"|"parse"|"manual",缺省 manual) }。确认卡明示将放入的路径、用户点「确认记住」后的一次调用:先按当前家庭查物品(不存在/已删/跨家庭 → NOT_FOUND,**零路径写入**——节点一个都不建),再复用 ensurePath 同款逻辑建缺失路径(用户已在确认卡看过完整路径 = 已确认,服务端不再拦),最后按 linkItem 同款版本条件更新挂上(同一版本链、同一重放识别)。**幂等:重复同路径 = 成功**——物品已挂目标节点时返回 { ok:true, already:true, item(当前版本) },version 不再 +1;响应丢失重试按「已挂目标」收敛。**挂靠失败绝不删物品**(物品已在,失败如实返回 VERSION_CONFLICT/NOT_FOUND,客户端提示先放「尚未归类」,物品与其原挂载原样保留,绝不静默改挂别处)。共享名称合并建议不在此做(整理位置入口另行裁决)。返回 { ok:true, already, replayed?(0 命中收敛时), item:{ item_id, version, updated_at }, path, created(与 path 等长的布尔数组), location_ids(与 path 等长的节点 id) }。写类 action,走 F2 双 marker 硬门(共享家庭必须携带一致的 expected_household_id + expected_scope_revision)。
- **parseLocation**(LLM,零写库):入参 { text }(去空白 1-200 码点)。既有树(≤120 节点,超出只送前两层)序列化进 prompt;返回 { ok:true, parse:{ segments:[{ name, type, confidence }](1-6 项;type 为服务端按深度派生填充的历史兼容字段,模型不再输出)、need_confirm, order_violation, merge_suggestions:[{ segment_index, existing_location_id, existing_name, reason }] } }。need_confirm 置真(任一):任一段 confidence<0.8;有序锚定未通过(含顺序违规,另置 order_violation);某段未锚定且无合并建议覆盖;模型自报不确定。本 action 绝不写库,响应永远是候选。
- **scanHousehold**(LLM,零写库):入参 { action:"scanHousehold" }。扫描池 = 未删除且未挂载(缺失/null/悬挂——悬挂件回流自愈)物品,updated_at 降序取前 30(增量:已挂载件不进池);空位置件进池、不送 LLM、归入 skipped(reason:"位置为空")。其余按 3 块并行(每块 ≤10 件,单块超时 15s,坏 JSON 重试一次),归并成候选树(同层 name_norm 去重,结构由构造保证)后追加一次轻量近义比对调用(输入仅各层名字列表,超时 10s 重试一次);任一块或近义调用失败 → 整体 AI_UNAVAILABLE(不部分成功)。返回 { ok:true, scan:{ scanned, unmounted_total, truncated, candidate_tree(节点含 confidence/need_confirm/children/merge_hints), synonym_groups:[{ level, names, reason }], mounts:[{ item_id, name, location_text, version, path, confidence, need_confirm, order_violation }](version 供 applyScan 作 expected_version), skipped:[{ item_id, name, reason }] } }。
- **applyScan**(向导确认结果的一次性提交,收敛式幂等):入参 { operation_id(非空 ≤64,失败重试/恢复原样复用), branches:[{ path }](纯结构确认,0-30 条), mounts:[{ item_id, expected_version, path }](逐件完整确认路径,1-30 件,branches 与 mounts 相互独立、无前缀约束,mount 完整 path 由本 action 沿路径建到最深层末段) }。参数结构校验失败 → INVALID_INPUT 且零写入。执行:每条 branch 与每件 mount 的完整 path 复用 ensurePath 同款逻辑(created_from:"scan")取末段节点,再版本条件更新挂载(派生标识 "scan:"+digest(operation_id+":"+item_id));逐件 0 命中回查:重放识别或已挂目标 → already,否则 conflict(绝不静默覆盖),物品不存在/已删/跨家庭 → not_found。返回 { ok:true, result:{ branches:[{ path, created, location_ids }], mounts:[{ item_id, status("mounted"|"already"|"conflict"|"not_found"), version?, current_version? }] } }。幂等为收敛式而非快照式:重放返回当前收敛状态,可能与首次响应不同(status 迁移),UI 按「继续完成剩余件」表述。
- **item_location_history(位置变更历史预留层,issue #18 v4)**:独立集合,append-only——只插入、不更新不删除,无唯一索引需求。字段:household_id(服务端派生,随写入隔离)、item_id、from_node_id(可 null)、to_node_id(可 null)、changed_at(ISO)、source("link" | "unlink" | "merge" | "apply_scan" | "compensate",与五个挂载写入方一一对应)。**唯一写入方是 locations 云函数**:全部挂载写入在版本条件更新处统一收口,真实变更(from ≠ to)追加一行;from == to 空变更不记;update_id/派生标识重放不进入历史写入,天然不重复;历史写失败不阻断挂载主流程——**best-effort:追加失败即静默跳过,不构成完整审计日志**,不得作为审计依据(挂载结果才是事实)。V1 无读取 UI、无查询 action,**本契约不承诺任何查询接口**;权限与其他集合同款「所有用户不可读不可写」(README 部署步骤 4)。

## households 协议(issue #34 P1-A:共享家庭生命周期/邀请/成员管理)

event 形如 { action, ... };统一响应 { ok:true, ... } 或 { ok:false, error:CODE, message(中文) }。身份只取 cloud.getWXContext().OPENID,index.js 先经 lib/household.js 三向解析(个人/共享/失败关闭同 itemsApi),event 里的身份字段一律忽略。handler 为纯函数(deps 注入 db/now/genId/genToken/sha256/memberKey/resolved/logger)。错误码:INVALID_INPUT、UNAUTHORIZED、NOT_FOUND(邀请或成员不存在/已失效;不在共享家庭)、FORBIDDEN(非 owner 执行 owner 独管操作)、ALREADY_IN_FAMILY(V1 边界:已在未解散共享家庭时 join/create)、OWNER_NOT_LAST(其他成员未全部退出时 owner leave/dissolve)、OWNER_MUST_DISSOLVE(最后一人 owner 只能解散不能退出)、HOUSEHOLD_UNAVAILABLE(元数据查询/写入异常,失败关闭,绝不回退、绝不伪装成业务错误)。

- **create**:入参 { action:"create", display_name?(去空白 1-30 码点,缺省「我的家」) }。新建空白共享家庭:全新随机 household_id("hh_f_"+随机 hex,与个人家庭 sha256 派生 id 不可混淆)、households 行 { dissolved:false, scope_revision:1, created_at }、创建者 owner 会员行、active 指针切到共享家庭;**不复制/不迁移任何私人数据**(决策 1)。已在任一未解散共享家庭 → ALREADY_IN_FAMILY(绝不静默转家);并发 create 由 active_household 唯一索引收敛(败者清理半成品后同样 ALREADY_IN_FAMILY)。返回 { ok:true, household_id, display_name, role:"owner", scope_revision:1, shared:true }。
- **inviteCreate**(owner):入参 { action:"inviteCreate" }。生成邀请令牌:服务端 crypto 随机 192bit(base64url,≥128bit 硬门),**库中只存 sha256(令牌)**(household_invites 唯一索引 token_hash;裸令牌绝不落库、绝不进日志,只在本次响应出现一次);默认 7 天过期、多次使用、可撤销。返回 { ok:true, invite:{ invite_id, token, expires_at } }。
- **inviteRevoke**(owner):入参 { action:"inviteRevoke", invite_id }。撤销令牌立即失效(inviteInfo/join 此后 NOT_FOUND);重复撤销幂等(already_revoked:true);非本家庭/不存在 → NOT_FOUND。返回 { ok:true, invite_id, revoked:true } 或 { ok:true, invite_id, already_revoked:true }。
- **inviteList**(owner):入参 { action:"inviteList" }。本家庭全部邀请元数据(created_at 降序),**不含令牌与令牌哈希**:{ invite_id, created_at, expires_at, revoked, expired(按当前时间计算) }。
- **inviteInfo**(持令牌者):入参 { action:"inviteInfo", token(16-128 字符) }。令牌有效(存在/未过期/未撤销/家庭未解散)→ 返回 { ok:true, display_name },**不暴露任何成员身份 PII、不暴露 household_id**;所有失效形态统一 NOT_FOUND「邀请不存在或已失效」(不给持令牌者探测面);集合查询异常 → HOUSEHOLD_UNAVAILABLE 失败关闭,绝不把异常伪装成「邀请不存在」。
- **join**(持令牌者):入参 { action:"join", token }。校验令牌 → 幂等(已是本家庭成员 → 补齐 active 指针,返回 joined:false, already_member:true,不重复 +1)→ 建会员行(role:"member", invited_by=邀请创建者摘要)→ scope_revision +1 → active 指针切到该家庭。**V1 边界**:已在其他未解散共享家庭 → ALREADY_IN_FAMILY 明确拒绝,绝不静默切换。无跨文档事务:写入顺序 会员行→修订号→指针→终验,「校验后家庭被解散」竞态由终验回滚(只删本次刚写的行,不触碰任何家庭数据);中断重试按幂等路径收敛。返回 { ok:true, joined:true, household_id, display_name, role:"member", scope_revision } 或幂等变体。
- **leave**:入参 { action:"leave" }。普通成员退出:先撤 active 指针(新请求立即回个人家庭)再删会员行,scope_revision +1。owner:其他成员未全部退出 → OWNER_NOT_LAST;只剩一人 → OWNER_MUST_DISSOLVE(最后一人只能解散,不产生无人管理的活跃家庭)。返回 { ok:true }。
- **removeMember**(owner):入参 { action:"removeMember", member_key(64 位 hex,memberList 下发的服务端派生摘要句柄) }。移除成员:对方 active 指针若指向本家庭则重置回其个人家庭(只删指向本家庭的指针行)、删会员行、scope_revision +1;**对方数据零触碰**(仅解除挂靠);不可移除自己(INVALID_INPUT);不存在 → NOT_FOUND。撤权即时性:指针删除后对方下一次解析即回个人家庭;已过写入硬门并在途的旧请求存在不可撤销窗口(诚实记录,无跨文档事务),其后旧作用域请求一律 FAMILY_SWITCHED/FAMILY_STALE_SCOPE 拒绝。
- **dissolve**(owner,仅当最后一人):入参 { action:"dissolve" }。软封存:households.dissolved=true(scope_revision +1)、全部邀请令牌作废(revoked=true)、owner active 指针切回个人家庭;**家庭数据(items/locations)永不删除**——封存后无人可再解析进入(三向验证失败关闭),数据原地保留。幂等可自愈:封存后中断的重试补齐清理(already_dissolved:true);还有其他成员 → OWNER_NOT_LAST。返回 { ok:true, dissolved:true } 或 { ok:true, dissolved:true, already_dissolved:true }。
- **memberList**(owner):入参 { action:"memberList" }。成员清单 { member_key, role, joined_at, invited_by, is_self }(owner 在前、其余按加入时间升序);member_key 为不可逆摘要句柄,系统不存昵称/头像等 PII。
- **status**:入参 { action:"status" }。轻量概要:个人 → { ok:true, household_id(存量算法派生), shared:false, role:null, scope_revision:null, display_name:null };共享 → { ok:true, household_id, shared:true, role, scope_revision, display_name }(P1-B 冷启动/前台恢复/成员变更后资格复核的依据)。
- **switch**(issue #45 十七轮切换家庭;#34 合同不弱化——只更新 active 指针 + 客户端作用域刷新,不另起炉灶):入参 { action:"switch", target:"personal"|"shared" }。
  - target="personal":**永远可回**;删除本成员的 active_household 指针行(无行 = 已在个人家庭,幂等成功 already:true),此后一切解析确定性回个人家庭;不触碰任何家庭数据。
  - target="shared":**须在册且未解散**——存在未解散共享家庭的会员行才可切;被移除/已退出/从未加入(无在册行)→ NOT_FOUND「你还没有加入共享家庭」;在册家庭的元数据缺行/字段非法/多个未解散在册行(异常态)→ HOUSEHOLD_UNAVAILABLE 失败关闭,绝不猜。
  - 指针切换为**单行原子更新**(active_household 唯一索引 (member_key) 保证指针唯一;读 → where 旧值条件更新 → 复核收敛);switch 不是成员变更事件,**不递增 scope_revision**;不迁移/不复制任何家庭数据(V2 搬迁工具不做)。
  - 返回新家庭 status 摘要(与 status 同口径):{ ok:true, target, already?(已在目标家庭时 true), household_id, shared, role, scope_revision, display_name };客户端据此按新家庭整页刷新地图/列表/快到期(骨架屏过渡,不拿上一家数据冒充)。
  - 撤权即时性同 removeMember:被移除后指针已重置个人家庭,switch shared 因无在册行被拒;已过解析的旧作用域写请求一律 FAMILY_SWITCHED/FAMILY_STALE_SCOPE 拒绝。
- **scope_revision 语义**:households.scope_revision 单调递增,create 初始化为 1,join/leave/removeMember/dissolve 各 +1(条件更新 CAS 收敛);itemsApi/locations 的共享家庭写操作携带的 expected_scope_revision 与之不一致 → FAMILY_STALE_SCOPE(见「F2 跨家庭写入绑定」)。修订号只增用于一致性前置校验,绝不作为授权凭据。
- **日志纪律**:只记 action/error/ms/count,绝不落 openid/member_key/裸令牌/令牌哈希/家庭名/household_id;异常不落详情,统一 HOUSEHOLD_UNAVAILABLE。

## parseLocation / scanHousehold LLM 契约(issue #18)
- system prompt 要点:家庭位置结构解析器;每条位置拆 1-6 段从大到小;每段名字必须逐字取自原文且按原文顺序,禁止改写概括调序;每段给 confidence(0-1),拿不准给低分、宁可低分不可编造;与【既有空间树】同层同名或近义的段在 merge_suggestions 给建议;只输出一个 JSON 对象。近义比对 prompt 只归「很可能指同一处」的名字组,拿不准不归。
- 服务端校验:JSON 提取容忍围栏(照 extractDraft 手法),坏 JSON 带错误重试一次仍失败 AI_UNAVAILABLE;segments 1-6 项、name 1-30 码点、confidence ∈ [0,1];模型输出不再要求 type(issue #30 PR A),响应 segments 的 type 一律由服务端按深度派生填充(历史兼容字段,供旧客户端展示);merge_suggestions 引用不存在节点则丢弃该条不失败,服务端对同名命中自动补全建议。
- **有序不重叠锚定**:每段在 normalizeName(text) 中求匹配区间,要求按段序单调递增且互不重叠;违规 → order_violation:true 且强制 need_confirm(高置信错序也不许默认勾选入库)。
- 防火墙不变量:两 action 执行前后 locations/items 集合零变化(离线测试直查断言);全系统只有 ensurePath(含 applyScan 内部复用)创建节点且只由用户确认后的客户端调用;need_confirm 草案 UI 必须呈现待核对状态(默认不勾选/标黄)。
- 耗时与超时:scanHousehold 最坏 ≈50s(3 块并行各 15s×2 + 近义 10s×2 串行)< 函数 60s 上限;客户端超时 parseLocation 30s、scanHousehold/applyScan 70s,均严格大于服务端对应预算,优先让服务端错误回来。模型 deepseek-flash、temperature 0.1、thinking disabled、response_format json_object;密钥只走云函数环境变量 DEEPSEEK_API_KEY(与 extractDraft 同名同法),缺失返回 AI_UNAVAILABLE 且 manual_fallback:true。

## transcribe 协议(PR2 新增,提请评审确认)
微信「同声传译」插件不支持个人主体,语音转文字改为独立云函数:原生录音(mp3/16k/单声道/24kbps,≤60 秒,约 180KB)→ base64 → 腾讯云一句话识别(请求含官方条件必填的 DataLen)→ 文字。这回到 issue #1 最初的模型最窄入口设计 transcribe(audio)→text,与 extract_items(text) 分离;无状态、不落库、输入输出即焚。

event = { audio_base64(非空,base64 后 ≤3MB,官方限额), voice_format(字母数字,如 "mp3") }。
- 校验失败 → { ok:false, error:"INVALID_INPUT", message(中文) },绝不发起调用
- 密钥(TENCENT_SECRET_ID/TENCENT_SECRET_KEY)缺失或 ASR 调用失败/超时(15s) → { ok:false, error:"ASR_UNAVAILABLE", message:"语音识别暂不可用…", manual_fallback:true },客户端回退文字输入
- 成功 → { ok:true, text(已 trim) }
- 日志只记:音频字符数、格式、耗时、错误码;绝不打印音频数据与识别结果。密钥仅云函数环境变量,绝不入库/入码/入日志。
- 超时 20 秒(config.json);除 wx-server-sdk 外零 npm 依赖(TC3 签名手写纯函数)。
